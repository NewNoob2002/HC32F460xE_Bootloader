# X1 可烧录测试版与 HIL 记录

测试日期：2026-10-12。目标是用户确认的 **X1 V1.3、HC32F460JEUA**，引脚沿用旧仓库。J-Link V9.76a 支持列表没有 JEUA 独立名称，使用同容量系列入口 `HC32F460xE`；识别 Cortex-M4 CPUID `0x410FC241`，VTref 约 3.41 V。Linux 主机自行发送真实面板轮询。

本记录保留V1.3阶段证据。后续已换接V1.5并验证同一BIN的MP识别、配置回读与运行状态，见 [V1.5实板HIL](x1_v15_hil.md)；电流/温度保护等完整电气验收仍待完成。

本版本是启动、面板通信、电池监测和双版本充电适配的测试基线；按键/关机、完整 LED 策略和 SOC 参数保存尚未完成，不能称为 X1 产品验收版。

## 真实 Linux 报文

从捕获版目标 RTT RAM 提取请求，不依赖人工发送或主机 mock：

| ID | 类型 | 请求载荷 / 帧长 | 当前处理 |
| --- | --- | --- | --- |
| `0x01` | query `0x00` | 2 / 26 字节 | 真实有效电池样本与已识别硬件版本编码为 60 字节信息响应 |
| `0x02` | query `0x00` | 2 / 26 字节 | 录制/充电快照编码为 32 字节控制响应 |
| `0x03` | set `0x02` | 8 / 32 字节 | 首字节录制状态同步，26 字节 ACK；发布失败/忙不执行同步 |
| `0x06` | set `0x02` | 88 / 112 字节 | 超出旧五消息契约，拒绝，尚未解释其产品语义 |
| `0x08` | set `0x02` | 28 / 52 字节 | 超出旧五消息契约，拒绝，尚未解释其产品语义 |

真实 `0x02` 请求：

```text
AA 44 18 14 02 00 00 00 00 00 00 00 02 00 00 00
00 00 00 00 01 00 A6 05 5D 81
```

CRC32 为标准 IEEE 反射多项式 `0xEDB88320`，上述头+载荷的 CRC 为 `0x815D05A6`，末尾四字节小端。响应保留字段显式清零。未知 ID、类型/长度非法、CRC 错误不执行业务。短读由 BSP 保留响应供重读；操作通知只通过完整读取计数确认，并且保留响应发布之后新生成的操作。

`0x04/0x05` 的业务尚未冻结，本版本对合法设置请求编码 26 字节 ACK，但 ACK 首字节为 **0**，不执行复位/断电。查询时电池样本无效则不发布正常信息，避免默认值冒充有效采样。

## 双版本充电实现与当前目标结果

- 运行时识别 `Unknown / GpioV13 / Mp2762V15Plus`。MP 地址 ACK 后读取 REG00/08/13 并检查保留位；健康 BQ 总线上的连续三次明确 MP 地址 NACK 才选择 V1.3。超时、总线异常或数据读取失败保持未知。识别成功后锁定，不在运行中因通信失败切换方案。
- V1.3：PA1 Type-C 检测，PB7 独立充电源检测，PB6 输入保留；PA4 使能与 PB10 电流选择初始化为低。有效新鲜电池温度处于约 0–45°C，且源稳定 1.5 s 后允许旧版 3A 选择；故障/陈旧/越界温度关闭充电。GPIO 快充状态代表使能/电流选择，不能替代电流实测。
- V1.5+：仅 MP2762 I2C 控制，不初始化旧充电输出；配置前禁用充电，保留系统供电/满充 OTP，不执行全寄存器复位。按旧产品参数配置预充门槛 6.6 V、预充 840 mA、快充 1600 mA，写后回读；840 mA 为 MP2762A Rev1.1 REG03 最大编码，也是旧 880 mA 请求的实际编码。状态来自 REG13，包括终止状态 3。读写失败不伪造成功，禁用无法确认时记录诊断。
- 自动探测只能确认充电拓扑；MP2762 没有独立器件 ID。首次启动前完全失联的新版 MP 与不存在的旧版 MP，纯 I2C 无法绝对区分；要消除该盲区，需要硬件识别电阻/GPIO或可靠出厂标识。`V1.5` 的线缆字段表示 MP2762 方案，不区分更晚 PCB 修订。

当前 V1.3 目标在 **402 ms** 自动识别完成；BQ 样本持续有效，无读失败：SOC 53%，电压 7535–7540 mV，温度 2992（0.1 K，约 26.05°C）。寄存器观察 PA1 高、PB7 低，PA4/PB10 低，充电保持关闭。没有主动做 Type-C 插拔、充电电流或温度刺激，MP2762 实板不在本轮资源中；两条软件路径、识别故障、锁定、温度与读写失败通过主机回归。

VTOR `0x8000`，SysTick CTRL 的 enable/tickint/clksource 位开启，I2C IRQ4/5/6 的 NVIC ISER 位开启；运行于主循环，无活跃异常，CFSR/HFSR 为 0。PB3 输出保持高，PA6 调度器启用、空闲低，脉冲起点推进到 420,000 ms，下一次截止 423,000 ms。两次时间/计数持续增加，没有观察到周期复位。

存在空读计数，未知 `0x06/0x08` 等请求仍被 Linux 读取；不得据“已支持消息完整读取”宣布所有 Linux 功能兼容。完整读取证明响应字节被主机时钟读出，本轮没有 Linux 端 CRC/业务解析日志。

最长时间是 1 ms SysTick 粒度下自由运行的固件观测，不能测量调试暂停、物理 PB3 瞬态或 PA6 波形宽度。没有逻辑分析仪，因此 PB3 连续波形、PA6 精确 1 ms/3000 ms、电气充电保护仍待实测。

## 失败与修复记录

1. 初次 MCP/GDB Flash 下载：GDB 返回下载进度且临时缓冲比较显示 matched，但服务日志有 Flash RAM 算法超时；不算成功。改用 SEGGER Commander connect-under-reset、100 kHz、BIN loadfile 隐式 reset/halt，再用独立会话 verifybin。后者两镜像通过。
2. 首个双版本镜像停在初始化故障：I2C2 100 kHz 沿用 `/2`，50 MHz PCLK3 下超过 LL 硬件高低计数范围。改为 `/8`，补回归后通过真实 BQ 采样。
3. 修正版烧录后，一次未复位的独立 Boot verifybin 在 `0x7BC` 报不一致。保留失败日志；随后 reset/halt 读回全部 Boot 字节一致，没有损坏证据。验证脚本固定复位暂停后校验，独立 Boot/App verifybin 均通过。具体瞬态读取原因未证明，不以重试删除原失败。
4. RTT 收集曾未正确恢复，日志改由暂停时读取实际 RTT RAM 保存；未把“无 RTT 文本”等同于目标不运行。
