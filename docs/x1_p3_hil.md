日期：2026-10-18。用户授权“flash it to the V1.5 board and test”，并在现场完成按键、USB-C 插拔与观察。原始日志、跟踪脚本与 RAM 快照位于忽略目录 `debug_artifacts/x1_b7_hil/`。

## 目标与部署

- J-Link 序号 `20781318`（与此前记录的 `63728769` 不同），HC32F460xE 系列入口，CPUID `0x410FC241`，VTref 约 3.30–3.35 V。
- 烧录前以不暂停方式备份整片 512 KiB Flash，SHA-256 `818e3894c670395b04e91b918f4762e299f6dd99b7dfb817ed1e60d46574c66e`（`before_full.bin`）。目标上为本工程某版 Boot 与带 `Pages/*` 界面的旧显示类 App（约 320 KiB），非 B6 镜像；参数扇区全 FF。用户确认目标为 X1 V1.5；新 App 启动后识别 `hardware=V1.5 mode=2`（MP2762 应答）。旧 App 在 `0x10000` 之后的残留扇区未擦除，不影响向量校验。
- 依次部署并独立 verifybin：B7 Debug App `cf5f8545…` → 冷启动修订 `90b5032d…` → Off 开机 `4471311b…` → 最终 `15f47542…`。Boot 始终为 `ba79317d…`（J-Link 比较后跳过）。最终产物哈希见 [App/README.md](../App/README.md)。
- J-Link 在本芯片上的复位（默认与 `RSetType 2`）实测留下 `0x4122`/`0x4120`（含 SWRF/WDRF），App 视为热启动直接开机；烧录后 Linux 会被重新上电，烧录前应先正常关机。

## 冷启动缺陷与修订

清零 RSTF0 后，USB-C 上电只留下 PINRF `0x0002`，无 PORF；TPL5010 RSTn 也接 MCU_RESET。MCU 关机时被保持在复位而非掉电（不可连接但 VTref 仍在）。原规则“仅纯 PORF 等待按键”因此永不触发：USB-C 插入直接拉起 Linux；按住 PA0 开机被当作热启动，同一段长按在 2 s 后请求关机，20 s 后断电。

用户批准按旧 X1 修订：仅软件复位直接运行，其余等待电源键；App 读后清除复位标志。修订后实测：USB-C 冷插入进入 Starting，10.03 s 超时释放 PB3 进入仅充电驻留，Linux 未启动。

外部供电驻留时按 PA0 不会复位 MCU，旧固件靠无限等待按键规避；新实现原先 Off 不处理按键导致无法开机。用户批准驻留中 2 s 长按重新开机，并在实板通过。

## 未完成与限制

- Linux 关机后未发 0x05，8 s 确认路径未在实板触发；需核实 Surveyor 是否实现该消息。
- 0x04 复位进入 Boot、低电量 180 s 关机、PB3 连续波形、充电电流/温度保护未测。
- 某次 Off 开机后 Linux 约 60 s 才出现（其他次约 8–24 s），原因未查。
- 驻留中保留的未读响应会阻止 D7 参数保存，直到 Linux 读取；本轮未改变。
- LED 结论来自 MCU 输出电平与用户目视，无光学/波形测量。
