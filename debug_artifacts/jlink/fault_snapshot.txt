Result
------
The Boot HardFault was not reproduced with the corrected, persistently
programmed Debug ELF.  The target reached bsp_i2c_slave_poll() in Recovery.
At that breakpoint and during the 20-reset regression:

  g_boot_fault_snapshot.magic = 0x00000000
  SCB->CFSR                  = 0x00000000
  SCB->HFSR                  = 0x00000000
  SCB->CPACR                 = 0x00F00000
  SCB->VTOR                  = 0x00000000
  active exception           = none (IPSR = 0)

Consequently there is no new Boot exception frame to symbolize:

  EXC_RETURN                 = not applicable
  active stack               = not applicable
  extended FP frame          = not applicable
  stacked PC                 = not applicable
  stacked LR                 = not applicable
  stacked xPSR               = not applicable
  MMFAR/BFAR                 = invalid because their CFSR validity bits are clear

CFSR decode
------------
MMFSR: no bits set.
BFSR:  no bits set.
UFSR:  no bits set, including NOCP.
HFSR:  FORCED=0, VECTTBL=0.

Important exclusion
-------------------
An earlier HardFault at PC 0x200180B6 occurred while bringing up the temporary
SRAM EFM programming helper with an invalid launch stack context.  It was not
produced by the Boot image.  The helper launch was corrected, the Boot fault
snapshot was cleared, and this event is excluded from Boot root-cause analysis.
